Problem
-------
scraper.py চালালে proxy দিয়ে request করলে ittefaq.com.bd সবসময় "403 Client Error: Forbidden"
রিটার্ন করছে, কিন্তু একই news_id-তে proxy ছাড়া (direct, নিজের নেটওয়ার্ক থেকে) request করলে
ঠিকমতো পেজ লোড হচ্ছে। proxies.jsonl-এ থাকা ৪টি proxy-ই (31.59.20.176, 45.38.107.97,
198.105.121.200, 64.137.96.74) একই user (gkxotuvl) এর অধীনে থাকা datacenter proxy — এবং
৪টি-ই একই ভাবে ব্লক হচ্ছে।

Why this happens (root cause)
------------------------------
এটা headers বা User-Agent এর সমস্যা না — HEADERS আগে থেকেই ঠিক আছে এবং ওই একই headers দিয়ে
direct connection কাজ করছে। ফারাকটা শুধু IP address। অর্থাৎ ব্লকটা application-level (title/
description missing ইত্যাদি) না, এটা network/IP-level ব্লক:

1. ittefaq.com.bd সম্ভবত Cloudflare বা এই ধরনের একটা WAF/anti-bot layer ব্যবহার করে, যেটা প্রতিটা
   incoming IP-র "IP reputation" চেক করে (datacenter vs residential, ASN, আগে থেকে abuse রিপোর্ট
   হয়েছে কিনা ইত্যাদি) — এটা একটা IP intelligence database (যেমন Cloudflare-এর নিজস্ব বা
   IPQualityScore-এর মতো সার্ভিস) থেকে আসে।
2. এই ৪টি proxy একটা shared/datacenter proxy provider-এর (residential না) — মানে এই একই IP
   গুলো আগে থেকেই অনেক scraper/bot ব্যবহার করেছে। ফলে ওই IP-গুলোর ASN/reputation আগে থেকেই
   "known bot/proxy" হিসেবে flag হয়ে গেছে অনেক WAF vendor-এর ডাটাবেজে।
3. তাই request এর headers, cookies, delay — সবকিছু ঠিক থাকলেও, শুধু IP reputation-এর কারণে
   Cloudflare/WAF সরাসরি 403 রিটার্ন করে দিচ্ছে, page content পর্যন্ত পৌঁছানোর আগেই।
4. উল্টোদিকে, তোমার নিজের বাসা/ISP-র IP (residential/home connection) সাধারণত "clean" থাকে,
   তাই সেখান থেকে direct request গেলে block হচ্ছে না।

এর আগে hproxy.com থেকে fetch করা free datacenter SOCKS5 proxy দিয়েও একই রকম 403 পাওয়া গিয়েছিল
(DigitalOcean, Performive ইত্যাদি datacenter ASN থেকে) — এটাই প্রমাণ করে যে সমস্যাটা proxy
provider-নির্বিশেষে, IP-এর ধরনের (datacenter) সাথে সম্পর্কিত, কোনো নির্দিষ্ট provider এর বাগ না।

How to solve
------------
1. সবচেয়ে সহজ (এখন কাজ করছে): যেহেতু তোমার নিজের নেটওয়ার্ক থেকে direct request block হচ্ছে না,
   এখন proxy ছাড়াই স্ক্রিপ্ট চালাও (proxies.jsonl খালি/সব লাইন commented রাখো)। কোড আগে থেকেই এই
   fallback সাপোর্ট করে — jsonl-এ কোনো active proxy না থাকলে সরাসরি (proxy ছাড়া) request পাঠায়।

2. যদি আসলেই proxy দরকার হয় (rate-limit এড়ানোর জন্য বা IP ঘন ঘন পাল্টানোর জন্য):
   - Datacenter proxy বাদ দিয়ে residential বা mobile proxy ব্যবহার করো (যেমন Bright Data,
     Oxylabs, Smartproxy, IPRoyal-এর residential plan)। এগুলো real ISP customer IP হওয়ায়
     WAF সহজে এদের bot হিসেবে ধরতে পারে না।
   - Free/shared datacenter proxy list (hproxy.com-এর মতো) এড়িয়ে চলো — এগুলোর বেশিরভাগ IP
     আগে থেকেই বহু সাইটে flagged।

3. proxy আসলে কী রিটার্ন করছে সেটা যাচাই করতে চাইলে সরাসরি curl দিয়ে টেস্ট করো:
     curl -x http://gkxotuvl:tax4ke2ae1s9@31.59.20.176:6754 -I https://www.ittefaq.com.bd/808305/test-news-title
   যদি এখানেও 403 আসে (যেমন এখন আসছে), তাহলে নিশ্চিত হওয়া যায় সমস্যাটা কোডে না, proxy IP-তে।

4. যদি সাইটটা Cloudflare-এর JS challenge/CAPTCHA দেখায় (শুধু headers status code দেখলে বোঝা
   যায় না, response body-তে "Just a moment...", "cf-mitigated" header, বা "cf-chl" শব্দ আছে
   কিনা চেক করো) — সেক্ষেত্রে শুধু requests লাইব্রেরি দিয়ে কখনোই কাজ হবে না, real browser engine
   (Playwright/Selenium/undetected-chromedriver) লাগবে যেটা JS execute করতে পারে।

Recommendation
--------------
আপাতত proxy ব্যবহার বন্ধ রেখে direct request দিয়ে scrape চালিয়ে যাও (এখন যেটা কাজ করছে)। ভবিষ্যতে
IP block হলে বা rate-limit লাগলে, তখন একটা paid residential proxy provider ব্যবহার করার কথা
ভাবা যেতে পারে — datacenter proxy (free বা paid) এই সাইটের জন্য কাজ করবে না।
